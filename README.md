# Говорим / Сүйлөйбүз — бот программы «Язык дружбы»

Telegram-бот для записи на бесплатные онлайн-уроки русского языка.
Собирает заявки, пишет их в Google-таблицу, показывает расписание и напоминает о занятиях.

Стек: [Bun](https://bun.com) + [grammY](https://grammy.dev) + TypeScript.

## Команды бота

| Команда | Что делает |
| --- | --- |
| `/start` | Приветствие и краткое описание проекта |
| `/join` | Пошаговая запись: имя → возраст → страна и населённый пункт → контакт |
| `/schedule` | Дни, время и длительность занятий |
| `/cancel` | Прерывает заполнение заявки |
| `/help` | Список команд |
| `/id` | Показывает твой Telegram ID — нужен, чтобы выдать права администратора |

## Команды администратора

Доступны только тем, чей Telegram ID перечислен в `ADMIN_IDS` через запятую.

| Команда | Что делает |
| --- | --- |
| `/applications` | Последние заявки с контактами и датой |
| `/export` | Присылает все заявки файлом `applications.csv` |
| `/stats` | Сколько всего заявок и подписчиков на напоминания |

Как выдать права: человек пишет боту `/id`, полученный номер добавляется в `ADMIN_IDS`,
бот перезапускается. Для остальных этих команд как будто не существует.

Заявки пишутся в `data/applications.jsonl` всегда — даже когда Google Sheets подключён.
Таблица нужна для общего доступа, а локальный журнал не даёт потерять заявку,
если таблица недоступна.

Напоминание о занятии уходит автоматически за час до урока в понедельник, среду и пятницу —
всем, кто хоть раз писал боту.

## Запуск

```bash
bun install
cp .env.example .env
bun run dev
```

Минимум для старта — `BOT_TOKEN`. Остальное можно добавить позже.

## Google Sheets (необязательно)

1. В Google Cloud создать проект и включить **Google Sheets API** и **Google Drive API**.
2. Создать сервисный аккаунт, скачать JSON-ключ.
3. Из ключа взять `client_email` и `private_key` в `GOOGLE_SERVICE_ACCOUNT_EMAIL` и `GOOGLE_PRIVATE_KEY`.
4. Создать таблицу и дать сервисному аккаунту доступ на редактирование (поделиться по `client_email`).
5. `GOOGLE_SHEET_ID` — часть URL таблицы между `/d/` и `/edit`.

Заголовок таблицы бот проставит сам при первом запуске.

**Это необязательный шаг.** Без него бот работает полностью: заявки всегда пишутся
в `data/applications.jsonl`, команда `/applications` показывает их в Telegram,
а `/export` присылает готовый CSV — его можно открыть в Excel или импортировать
в Google Таблицы вручную. Интеграция нужна, только если хочется, чтобы строки
появлялись в общей таблице сами.

## Быстрый запуск на своём компьютере

Двойной клик по `start-bot.cmd`. Окно должно остаться открытым — пока оно открыто,
бот принимает заявки. Если бот упадёт, скрипт поднимет его сам через 5 секунд.

Это временное решение: бот работает, только пока включён компьютер.
Постоянную работу даёт хостинг — см. раздел ниже.

## Структура

```
src/
  index.ts                 — точка входа: загрузка данных, планировщик, старт
  bot.ts                   — инстанс бота, подключение хендлеров, обработка ошибок
  config.ts                — переменные окружения и их валидация
  content.ts               — все тексты сообщений
  context.ts               — тип контекста и данные сессии
  types.ts                 — модель заявки
  validation.ts            — проверка ответов формы, покрыта тестами
  health.ts                — health-эндпоинт для хостинга
  keyboards.ts             — кнопки меню и запроса контакта
  handlers/
    commands.ts            — /start, /help, /schedule
    join.ts                — пошаговая форма записи и /cancel
    subscribe.ts           — запоминает всех, кто писал боту
    admin.ts               — /applications и /stats для администраторов
  services/
    sheets.ts              — запись заявки в Google Sheets
    storage.ts             — подписчики и журнал заявок
    session-storage.ts     — незаконченные формы переживают перезапуск
    reminders.ts           — напоминания по расписанию
    csv.ts                 — выгрузка заявок в CSV
```

## Хостинг

Бот работает круглосуточно только на сервере. В репозитории готовы `Dockerfile`,
`railway.json` и `render.yaml`.

Два важных момента:

1. **Постоянный диск.** `DATA_DIR` должен указывать на примонтированный диск (`/data`),
   иначе при каждом передеплое обнулится список подписчиков для напоминаний.
2. **Переменные окружения.** `.env` в репозиторий не попадает — `BOT_TOKEN` и ключи Google
   задаются в панели хостинга вручную.

Когда задана переменная `PORT`, бот дополнительно поднимает health-эндпоинт на `/` —
это нужно платформам, которые считают сервис живым только при открытом порте.

```bash
curl http://localhost:3000/
# {"status":"ok","startedAt":"...","uptimeSeconds":42}
```
